# 仓库交接：Heavy 做到哪了、为什么这么分、坑在哪

交接日：2026-11-14（原维护 `zjfklss` → 接手 `QrFsh`）  
设计原理、2027 规则映射、串口协议与未拍板项另见 [`重装自动对矿技术路线.md`](重装自动对矿技术路线.md)，标定原理与数据约定见 [`圆点标定操作流程.md`](圆点标定操作流程.md)。本文只讲仓库结构、当前真实现状、分支来历和踩过的坑。

## 1. 这仓库到底有几条线（分支怎么选）

`Heavy` 仓库里同时放过英雄自瞄、重装吊射、重装自动对矿三条线。**GitHub 当前默认分支（`origin/HEAD`）还停在 `feature/tongji-hero`**，刚克隆下来不会在自动对矿分支上，需要自己切到 `feature/heavy-ore-sim`：

```bash
git clone https://github.com/zjfklss/Heavy.git
cd Heavy
git checkout feature/heavy-ore-sim
```

各分支的实际关系：

- **`feature/heavy-ore-sim`**（当前）：从 `tongji-hero` 切出后删光了自瞄栈（`src/`、`tasks/`、`tests/`、`assets/`），只留下可复用的 `tools/`、圆点标定工具与配置、`io/`，再把港科 RM2026 仿真运行时塞进 `ore_sim/hkust_runtime/`。**自动对矿工作全在这条分支。**
- **`feature/tongji-hero`**：无 ROS 英雄自瞄（目录仿同济 `sp_jlcv_aimer`），自带 `rm_simulation`。英雄打弹/前哨用它。
- **`feature/hero-ros2`**：从实车 `jlcv@10.46.123.97:~/jlauto-aim/hero/src` 拉回的 ROS 2 英雄代码，修了三件事：前哨站锁最高层（不再乱跳下面板）、目标丢失时发 `(0,0,0)` 绝对角导致近距离莫名低头、顺逆时针小陀螺命中不对称。
- **`feature/custom-client`**：早先尝试的「重装吊射」（NUDT 定位 + ITL 高抛弹道 + CustomClient），路径硬编码在车上 `/home/jlcv/heavy`，与对矿是两回事。
- **`main`**：早期合并过一次 `tongji-hero` 的快照，**里面没有 `ore_sim`**，别从它拉新分支做对矿。

## 2. 对矿分支做到哪了，没做哪

**已通的**：
- `ore_sim/hkust_runtime/` 里 5 个 ROS 2 包源码完整进库，已在 Ubuntu 26.04 + ROS 2 `lyrical` 上编译通过。
- 只起 MuJoCo 仿真场景（`arm_exchange_sim.launch.py`）能跑起来：20 个 body、5 个应用插件、左右两路 640×640 相机、`/joint_states` 有数。

**没通的 / 仓库里没有的**：
- **对矿业务代码一行还没写**（没有 HEVC 图传解码、没有赛事 MQTT、没有资源站检测模型、没有取矿/装配状态机、没有 `0x0310`/`0x0311` 串口收发）。
- **`sim_host.launch.py` 与感知节点还没联调验证过**。
- **`weights/` 没提交进 Git**：得自己从 [Hugging Face](https://huggingface.co/hkustenterprize/RM26_engineer_exchange_model) 下，放到 `ore_sim/hkust_runtime/weights/`（`yolo_v10.12_openvino_model` 与 `litehrnet30_v11.0_openvino_model`）。
- **`.venv` 没提交进 Git**（原机上约 953 MB）：换电脑后按 [`readme.md`](../readme.md) 自备包含 `mujoco, hppfcl, scipy, openvino, glfw, readerwriterlock, rclpy` 的环境，用 `VENV=... ./scripts/build.sh` 编。
- **仿真插件还缺三块**：港科原仓只有「机械臂 + 科技核心 + 模拟下位机」，资源站磁吸抓拔（`ResourceStation`）、四级双核心裁判判定（`TechCoreReferee`）、图传压缩延迟劣化（`LinkEmulator`）都没写。

## 3. 几个直接省你时间的技术坑

1. **`system_config.yaml` 默认写了 `GPU`**：仓库里的 `ore_sim/hkust_runtime/core/arm_exchange_core/system_config.yaml` 把 `yolo_device` 和 `hrnet_device` 都改成了 `GPU`。换了电脑如果没装 OpenVINO 核显/GPU 驱动（NEO）会直接起不来，先改成 `CPU` 跑通流程再说。
2. **别把海康相机代码接到对矿主链路里**：分支里留着 `io/hikrobot/` 和 `CMakeLists.txt` 里的海康支持，只是因为标定和老资产顺手留了下来。**2027 自动对矿跑在自定义终端上，图像源是官方图传 UDP 3334（HEVC 流），不是插车上电脑的 USB 海康相机**。无图传硬件时用普通 USB 相机加软件 x265 压流模拟即可。
3. **之前踩过海康序列号写死的坑（做自瞄分支时注意）**：英雄自瞄以前把相机序列号写死在代码/配置里，换一块主板或换个相机直接报 `not found`。以后任何抓图入口别写死序列号。
4. **MuJoCo 仿真“按键盘没反应”不是模型坏了**：港科仿真默认只起物理节点，键盘控制要单开终端起 `arm_exchange_sim operator_input` 并传可读的 `/dev/input/event*`（需要账号在 `input` 组），且 GLFW 窗口要有焦点。
5. **机械现在就可以先做验证道具，不用等整车**：视觉 PnP 对的不是整台车，而是科技核心和装配柱前端那 **80×80 mm MARK 框（`TL/TR/BL/BR`）** 与 **Ø36 mm / 100 mm 插入段**（以及能量单元圆柱实物）。让机械按 2027 规则尺寸切一块带 MARK 框的木板/3D 打印件加一根圆柱，就可以提前测图传视野下的 PnP 精度和夹爪捕获范围。

## 4. 原赛季时间轴与实际情况的偏差

队内《2027 赛季时间轴》里，重装视觉列（原表格里还叫「英雄视觉」）写的节点明显偏乐观：

| 时间段 | 原表写的视觉目标 | 实际现状与判断 |
| --- | --- | --- |
| 10.28–11.10 | 新人培训、老代码修问题、定抓矿技术路线 | **已完成**：技术路线、开源调研、英雄 ROS 2 问题修复、对矿分支剥离 |
| 11.11–11.17（当前周） | 新代码适配 + **完整自动对矿仿真** | **未达标**：只搭进了港科仿真底座并跑通空场景，完整取矿/装配/图传仿真差得还远 |
| 11.18–12.01 | IMM 跟踪对比 + 老工程尝试自动对矿 | 原表几乎每周都把「英雄自瞄」和「自动对矿」两件互不依赖的事绑在同一格 |
| 12.09–12.22 | 新重装出车自瞄 + **完成自动对矿基本流程** | 若按实车进度，12 月底前能出替代道具视觉 PnP + 串口闭环就不错了 |
| 02.10–02.12 / 03.24–03.26 | 中期形态考核 / 完整形态考核 | 两个节点都需要出考核视频 |

**建议怎么拆开做**：把「英雄自瞄」和「重装自动对矿」彻底当成两条独立线程排期。先找队长确认本赛季到底打不打 **RMUC**——如果只打 **RMUL（高校联盟赛）**，2027 联盟赛规则取消了能量单元装配，重装只需要换装 42mm 发射机构，那自动对矿就没必要硬上。如果打 RMUC，先把仿真里「权重 + `sim_host` 感知」跑通，再用替代道具测通「图传 → 12 点 PnP → 手眼 → 关节目标」，最后再去补四级双核心和插件。

## 5. 注释核对

本分支自己的 C++（`calibration/`、`io/`、`tools/`）只在会看错的地方加了注释：手眼两条路径的坐标方向相反、圆点阵 180° 翻转、`k3` 固定为 0、海康按序列号匹配且 `vid_pid` 为空所以不做 USB 复位、弹道只搜 1.5 rad 以下的低伸解、欧拉角在 0/π 附近不可分。`tools/extended_kalman_filter.cpp` 里 NIS 阈值 0.711 原来的注释写成「χ² 95%」，实际是 χ²(4) 的 5% 分位，而且大于它就记失败，滤波器正常时几乎每次都记。注释已改，**阈值没改**。

`ore_sim/hkust_runtime` 的 Python 和上游逐文件相同，只改过三个 `scripts/` 和这份 README。上游注释留着，没有再写一套中文。

其它分支只读过，文件没改：

- `feature/tongji-hero`：`docs/自瞄入门教学.md`、`docs/英雄自瞄代码导读.md`、`docs/hero.md` 和代码对得上。跟踪、定头开火的注释在 `tasks/` 里。
- `feature/hero-ros2`：弹道和 MPC 的说明在 `solve_angle/include/ballistic_solver.hpp`。同目录的 `README.md` 整篇是串口驱动的说明，标题也写成 `jlcv_serial_driver`，不要拿它当弹道文档。`package.xml` 的 description 还是 ROS 模板。
- `feature/custom-client`：`docs/开源对照.md`、`docs/修改说明.md`、`docs/运行方式.md`，以及 `vendor/custom_client/linuxsender1/docs/newcomer_guide.md`（图传 H264 按 300 字节拆进 `0x0310`）值得留。`linuxideo/超分模型环境部署.md` 开头是对话口气，正文是 5090 必须用 CUDA 12.8，4060 的 cu121 装上去会报 `no kernel image`。
- `main`：停在并入 tongji 英雄之前的旧树，文档比 `feature/tongji-hero` 少。英雄线以 `feature/tongji-hero` 为准。
