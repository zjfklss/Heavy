## 0. 从 ROS 转过来：先把这几件事想通

本项目**不是 ROS 工程**，没有 `colcon`、没有节点和话题、没有 launch 文件。对照关系：

| 你在 ROS 里习惯的 | 在本项目里 |
|---|---|
| `colcon build` | `cmake --build build -j4`（构建目录是 `build/`，已经配置好） |
| `ros2 run pkg node` | `./build/hero --show`（一个可执行文件，一个进程） |
| 节点之间发话题 | 同一进程里的线程 + 队列（`tools/thread_safe_queue.hpp`） |
| 参数服务器 / launch 里的参数 | 一个 YAML：`configs/hero.yaml`，改完重启即可，不用重新编译 |
| `rqt_plot` / `rviz` | `--show` 调试面板；另外绘图数据走 UDP `127.0.0.1:9870` |
| `ros2 bag` | `~/records/*.avi` 录像 + `./build/hero --video` 离线回放 |
| 单元测试 `colcon test` | `build/tests/hero/hero_test configs/hero.yaml` |

最常用的四条命令：

```bash
cd ~/Heavy
cmake --build build -j4                         # 改了 C++ 代码之后编译
build/tests/hero/hero_test configs/hero.yaml    # 跑逻辑测试（不接硬件）
build/hero --check-config configs/hero.yaml     # 只检查配置写得对不对
./build/hero --show --no-fire                   # 上车：跟随但不开火，先观察
```

要点：
- **只改了 `.yaml`** → 不用编译，重启 hero 就行。**改了 `.cpp/.hpp`** → 必须先编译。
- 编译出错时先看第一条 `error`，后面的大多是连带报错。
- 没有"节点崩了会自动重启"的东西：hero 退出就是退出了，看 `logs/` 里最新的日志。

## 1. 相机模型：像素和世界怎么对应

**针孔模型。** 空间中相机坐标系下的一点 `(X, Y, Z)`，投影到图像上的像素 `(u, v)`：

```
u = fx · X/Z + cx
v = fy · Y/Z + cy
```

- `fx, fy`：焦距（单位是像素，不是毫米）；`cx, cy`：光心（图像中心附近）。
- 把它们排成一个 3×3 矩阵就是**内参矩阵**，配置里的 `camera_matrix: [fx, 0, cx, 0, fy, cy, 0, 0, 1]`。
- 实际镜头会让直线弯曲，这叫**畸变**，用 5 个系数 `[k1, k2, p1, p2, k3]` 描述，配置里的 `distort_coeffs`。

**为什么要标定。** 内参和畸变是镜头的物理属性，每个镜头不一样，必须用棋盘格标出来；标不准，后面的距离和角度全都带系统误差。
标定流程见 `docs/相机标定操作流程.md`。

**手眼标定（相机 ↔ 云台）。** 相机不在云台转轴中心上，而且装的时候有小角度偏差，所以还需要两个量：
- `R_camera2gimbal`：相机坐标系到云台坐标系的旋转；
- `t_camera2gimbal`：相机在云台坐标系里的位置。

`Solver::solve()` 里有这一行，就是在用它们：
```cpp
armor.xyz_in_gimbal = R_camera2gimbal_ * xyz_in_camera + t_camera2gimbal_;
```
再乘上电控回传的云台姿态 `R_gimbal2world_`，就得到**世界系**坐标（`armor.xyz_in_world`），这是后面滤波的统一参考系。

**练习：** 在 `configs/hero.yaml` 里把 `fx` 改大 5%，用 `--video` 回放一段录像，观察距离估计（面板里的世界坐标）怎么变，再改回来。理解"焦距错了，距离就按比例错"。

## 2. PnP：由图像上的 4 个点求装甲板的位置和朝向

**问题。** 已知装甲板的真实尺寸（小装甲 135 mm 宽、灯条 56 mm 高）和它在图像上的 4 个角点，求装甲板相对相机的位置和姿态。

**做法。** 这叫 PnP（Perspective-n-Point）。代码里直接调 OpenCV：

```cpp
// tasks/auto_aim/solver.cpp: Solver::solve()
cv::solvePnP(object_points, armor.points, camera_matrix_, distort_coeffs_,
             rvec, tvec, false, cv::SOLVEPNP_IPPE);
```
- `object_points`：装甲板 4 个角点在**装甲板自身坐标系**里的 3D 坐标（文件顶部的 `SMALL_ARMOR_POINTS` / `BIG_ARMOR_POINTS`，原点在板中心，板面是 y–z 平面）。
- `armor.points`：检测网络给出的 4 个角点的像素坐标。
- 输出 `tvec` 是装甲板在相机系的位置，`rvec` 是旋转向量（轴角表示），再经 `cv::Rodrigues` 转成旋转矩阵，最后用 `tools::eulers` 取出 yaw/pitch/roll。
- `SOLVEPNP_IPPE` 是专门针对"平面物体"的解法，装甲板是平面，所以用它。

**一个重要经验：yaw 最不准。** 装甲板正对相机时，板子微微转一点，4 个角点在图像里几乎不变，所以 PnP 给出的装甲板朝向角（yaw）噪声大、距离越远越明显；位置 `(x, y, z)` 则相对准得多。
`Solver::optimize_yaw()` 就是为这个写的：假设装甲板的 pitch 是固定的（约 ±15°），在一个范围内逐度搜索 yaw，让"重投影回图像的 4 个点"与检测到的点最接近（`armor_reprojection_error`）。
注意：当前 `solve()` 里调用它的那一行是**注释掉的**（`// optimize_yaw(armor);`），目前没有启用。要启用前先想清楚：它假设了 pitch 已知，对平衡步兵这类不成立（代码里 `is_balance` 的判断就是为此）。

**练习：** 打开面板看 `pnp_x/pnp_y/pnp_z`（这些量会通过 UDP 绘图发出），对一个静止的目标，比较位置和 yaw 哪个更"抖"。

## 3. 卡尔曼滤波：用有噪声的观测估计"真实"的状态

### 3.1 直觉

每一帧的 PnP 结果都有噪声，而且会因为遮挡、丢帧而缺失。我们既要"平滑"，又要能在没有观测时"外推"。卡尔曼滤波做两件事，每一帧循环：

1. **预测**：根据运动模型，把上一帧的状态推到现在，同时**增大不确定度**（因为推测会引入误差）。
2. **更新**：拿到观测后，按"模型有多不确定 / 观测有多不确定"的比例，把预测和观测混合，**减小不确定度**。

核心量只有两个：
- **状态 x**：我们要估计的东西；
- **协方差 P**：对 x 的不确定程度（越大越不确定）。

### 3.2 本项目的状态向量（11 维）

```
x = [ x, vx, y, vy, z, vz, a, w, r, l, h ]
      │   │   │   │   │   │  │  │  │  └─ l,h：另一对装甲板的半径差、高度差（4 板车用）
      │   │   │   │   │   │  │  │  └──── r：旋转半径
      │   │   │   │   │   │  │  └─────── w：整车角速度 (rad/s)，正负是转向
      │   │   │   │   │   │  └────────── a：其中一块装甲板的朝向角
      └───┴───┴───┴───┴───┘ 整车旋转**中心**的位置和速度（不是装甲板的位置！）
```

为什么跟踪"整车中心"而不是装甲板：车在小陀螺时，每一帧看到的是不同的装甲板，位置在跳；但**中心**是平滑运动的。装甲板位置由中心推出来：
```cpp
// Target::h_armor_xyz
armor_x = x[0] - r * cos(angle);   // 中心 - 半径 × 方向
armor_y = x[2] - r * sin(angle);
```
这就是"观测函数 h"：状态 → 观测量。

### 3.3 对应到代码

| 概念 | 代码位置 |
|---|---|
| 预测（`P = F P Fᵀ + Q`，`x = f(x)`） | `ExtendedKalmanFilter::predict`；`Target::predict` 里构造 F 和 Q |
| 更新 | `ExtendedKalmanFilter::update` |
| 观测量 z = (yaw, pitch, distance, 朝向角) | `Target::update_ypda` |
| 观测函数 h 和它的雅可比 H | `Target::h_armor_xyz`、`Target::h_jacobian` |
| 观测噪声 R（`4e-3, 4e-3, 1, 2e-1`） | `update_ypda` 里的 `R_dig` |
| 过程噪声 Q（v1：平动加速度方差，v2：角加速度方差） | `Target::predict`；构造 Target 时的 `v1, v2` 参数 |
| 初始协方差 P0 | `tracker.cpp` 里的 `P0_dig_car` / `P0_dig_outpost` |

**为什么叫"扩展"(EKF)。** 观测函数 `h` 是非线性的（有 cos/sin、有从 xyz 到球坐标的变换），不能直接用矩阵乘，所以在当前状态附近做线性化，这个线性化矩阵就是**雅可比 H**（`h_jacobian`）。

### 3.4 怎么调参（凭直觉）

- **R 大**（不信观测）→ 输出更平滑，但**跟不上**快速变化；
- **Q 大**（不信模型）→ 更**跟手**，但更抖；
- 调的就是"信模型还是信观测"的比例。前哨站的 v1 = v2 = 0，意思是"我完全相信它不平动、匀速转"，所以滤波结果非常稳，代价是转向变了它改不过来——这正是我们后来要加转向监测的原因（见导读）。

### 3.5 NIS：判断滤波器是不是"疯了"

`update` 里算了 NIS（归一化新息平方）：`residual ᵀ S⁻¹ residual`。直觉：**观测和预测差了多少个"标准差"**。
长期偏大，说明模型和现实对不上。`Target::update` 里用最近一段时间 NIS 失败率超过 40% 就判丢失（`Bad Converge Found`）。

> 阅读提示（留给后来人确认）：`extended_kalman_filter.cpp` 里 NIS 阈值的注释写的是"自由度 4、置信 95%"，但 0.711 实际是卡方分布(自由度 4)的 **5% 下分位数**，95% 上分位数应是 9.49。也就是说这个阈值比注释说的严格得多。它目前也在起作用（会导致失败率偏高），改动前请先用录像评估影响，不要凭这条注释直接改。

**练习：**
1. 在 `Target::predict` 里把前哨站以外的车的 `v2`（角加速度方差）从 400 改成 40，用小陀螺录像回放，观察估计的 `w` 曲线变化。
2. 画出 `nis` 随时间的曲线（UDP 绘图里有 `nis`、`recent_nis_failures`），找一段丢目标的时刻，看 NIS 是不是先升高。

## 4. YOLO：检测网络输出了什么

**任务。** 输入一帧图像，输出每块装甲板的：位置（框和 4 个角点）、**颜色**（红/蓝）、**数字**（几号车）、置信度。

**本项目的流程**（`tasks/auto_aim/yolo.cpp` 做分发，`yolos/yolov5.cpp` 是当前使用的实现）：
1. **预处理**：缩放到网络输入大小（记下缩放比例 `scale`，后面要换算回原图坐标）；
2. **推理**：用 OpenVINO 在 CPU 上跑（配置 `device: CPU`、`yolov5_model_path: ../assets/yolov5.xml`，同目录要有同名 `.bin`）；
3. **后处理**（`postprocess`）：
   - 对每个候选先用置信度阈值过滤，`score = sigmoid(...)`；
   - 在颜色分数和数字分数里各取最大的那一类；
   - **NMS**（`cv::dnn::NMSBoxes`）：同一块板会被框出好几个重叠的框，按置信度只留最好的；
   - 把 4 个角点换算回原图，构造 `Armor` 对象。
4. 交给 `Solver::solve` 做 PnP（第 2 节）。

**常见误解：**
- 网络输出的是**像素坐标**，距离/朝向是后面 PnP 算出来的，网络本身不知道距离。
- 角点顺序要和 `SMALL_ARMOR_POINTS` 里的顺序严格一致，否则 PnP 会得到镜像或翻转的解。换模型或改训练标注时最容易在这里出问题。
- 想换网络：改 `yolo_name`（`yolov5` / `yolov8` / `yolo11`）和模型路径即可；但注意导读里写的——当前多线程流程只验证过 `yolov5`。
- 速度：`detection_fps` 约 80，`acquisition_fps` 约 165。检测比采集慢，所以不是每帧都检测，延迟主要来自这里。

**练习：** 用 `--video` 回放一段录像，把 `score_threshold_`（`yolos/yolov5.hpp` 里，当前 0.7，改完要重新编译）调高/调低，观察误检和漏检的变化。

## 5. 把它们串起来（一帧的旅程）

```
图像 ──YOLO──> 4 个角点(像素)
        └─PnP──> 装甲板在相机系的位置/朝向
           └─ R_camera2gimbal / t / R_gimbal2world ──> 世界系位置
              └─EKF──> 整车中心、转速、半径(平滑，且能外推)
                 └─Shooter──> 弹道解算 + 开火时机 ──> yaw/pitch/开火 ──串口──> 电控
```

遇到问题，从后往前问三个问题，能快速定位到哪一层出了错：
1. 指令是不是在**跳**？→ 看 Tracker 是不是在反复丢失重置（日志里 `new target set` 的频率）。
2. 估计的位置是不是**不准**？→ 检查手眼标定、内参，或者 PnP 的角点顺序。
3. 估计**平滑但滞后/偏差**？→ 看 EKF 的 R、Q（第 3.4 节），以及延迟补偿参数 `shoot_delay`。
