# 英雄自瞄代码导读

给新队员和接手的人。代码里的注释讲"某段为什么这样写"，这份文档讲"整体怎么串起来、出了问题先看哪里"。
最后更新：2026-11-11（前哨站定头抖动、命中率相关的一轮修改之后）。

## 1. 数据流

```
相机 ──> 检测(神经网络) ──> 解算到世界系 ──> Tracker/Target(EKF 跟踪) ──> Shooter ──> 串口 ──> 电控/云台
 io/camera   tasks/auto_aim      Solver            tasks/auto_aim          tasks/auto_outpost   io/hero
                                  ▲
                      串口回传的云台姿态(IMU，按图像时间戳对齐)
```

入口在 `src/hero.cpp` 的 `run_hero()`：
- 视觉线程：取图 → 检测 → 用对齐后的姿态解算世界系坐标 → `Tracker::track()`。
- 决策线程（`Decisions` 类）：拿最新目标反复调用 `Shooter::shoot()`（最快每 1 ms 一次，实测约 370 Hz），把指令发给串口。所以**指令频率远高于检测帧率**。

## 2. 各模块在哪

| 目录/文件 | 作用 |
|---|---|
| `src/hero.cpp` | 主流程与决策线程、命令行参数 |
| `tasks/auto_aim/tracker.cpp` | 每种敌人一个 `Target`，决定"现在打哪个" |
| `tasks/auto_aim/target.cpp` | 单个目标的 EKF 与状态机（LOST/DETECTING/TRACKING/TEMP_LOST） |
| `tasks/auto_outpost/shooter.cpp` | 把目标变成云台指令；**定头**打法、开火窗口都在这里 |
| `io/hero/hero_serial.cpp` | 串口协议（帧格式见函数注释） |
| `tools/` | EKF、弹道(`trajectory`)、日志、绘图(`plotter`) |
| `configs/hero.yaml` | 实机配置；`configs/simulation/hero.yaml` 是仿真配置 |
| `tests/hero/hero_test.cpp` | 逻辑测试（不接硬件） |

## 3. 关键概念

**EKF 状态**：`x vx y vy z vz a w r l h`。`x,y,z` 是整车**旋转中心**，不是装甲板；装甲板位置由中心+半径+角度推出。

**定头**：英雄只做固定瞄准。云台瞄旋转中心正前方不动，等对应装甲板转到枪口前那一刻开火。
开火条件是 `0 <= phase_error <= 窗口`，`phase_error` 的符号取决于旋转方向，**所以转向 w 必须判对**。

**前哨站的特殊性**：
- 它不平动，所以瞄准点做了"锁存"，不跟随每帧估计（见 `Shooter::get_outpost_front` 注释）。
- 转速 w 在加锁时一次性设成 ±0.8π，之后滤波器不再更新，转向变化靠 `Target::monitor_outpost_direction` 纠正。
- 每转一圈会有板子短暂看不见，所以它的 temp-lost 上限比普通车大得多（`outpost_max_temp_lost_count`，默认 120 帧）。

**串口**：视觉发 13 字节（pitch、yaw、控制位 0/1/2），电控回 16 字节（姿态、弹速、标志位）。
**云台是否听从指令由电控/遥控器的自瞄使能决定，协议里没有这个按键的字段，视觉侧无法替代。**

## 4. 常用命令

```bash
cd ~/Heavy
cmake --build build -j4                                   # 编译
build/tests/hero/hero_test configs/hero.yaml              # 逻辑测试
build/hero --check-config configs/hero.yaml               # 只校验配置
./build/hero --show                                       # 实机 + 调试面板
./build/hero --show --no-fire                             # 跟随但不开火（只看不打）
./build/hero --video <录像.avi>                           # 离线回放，不碰云台
./build/hero --simulation                                 # 接 rm_simulation 仿真
```

停止 hero 用 `pkill -INT -x hero`。**不要用 `pkill -f <字符串>`**：命令行里含该字符串时会把你自己的 shell 一起杀掉。

调试数据：绘图数据通过 UDP `127.0.0.1:9870` 发出（JSON，含 `command_yaw/command_pitch/control` 等），可以自己写个小脚本抓下来分析；日志在 `logs/`。

## 5. 可调参数（`configs/hero.yaml`，标“可选”的键不写则用默认值）

| 键 | 含义 |
|---|---|
| `shoot_delay` | 发出开火指令到弹丸射出的延迟(s)，影响开火时机 |
| `max_temp_lost_count` | 普通目标丢帧多少帧判丢失 |
| `outpost_max_temp_lost_count` | 前哨站专用，可选，默认 120 |
| `outpost_fire_window` | 前哨站开火相位窗口(rad)，可选，默认 0.01 |
| `fire_refractory_ratio` | 防连发：两次开火最小间隔 = 比例 × 相邻两板经过时间；0 关闭，可选，默认 0.5 |
| `layer_height_threshold` | 对前哨站已不起作用（固定打最高层），仅为兼容保留 |

## 6. 出问题先看哪里（经验清单）

1. **帧率不对**：看日志 `[Vision] acquisition_fps`，正常约 165。如果只有 ~24，先 `lsusb -t`：相机如果挂在 480M 的总线上，就是 USB 降到 2.0 了，换 USB3 口/线重插。
2. **云台抖动**：先 grep 日志里 `new target set` 的频率。如果每隔几秒就一次，是 tracker 在反复丢失重置，不是瞄准公式的问题。
3. **前哨站命中率低**：看有没有 `[Target] outpost direction corrected`；转向判反会让整个开火窗口错位。
4. **打一次发两个开火包**：窗口很窄但决策线程每毫秒跑一次，所以要去抖，见 `fire_refractory_ratio`。
5. **自瞄时的 ±0.1° 小台阶**：车体会前后晃，云台头重，属于正常现象，不要当 bug 追。

## 7. 已知的遗留问题

- `Shooter` 里的 `armor_state`（已打/跳过状态机）操作的是目标的局部拷贝，没有写回，实际不生效。
- Tracker 在前哨站 TEMP_LOST 期间（最长约 1.5 s）不会切换到别的目标。
- 转向监测的阈值（0.5 s 窗口、0.7 rad、连续两窗）和"0.75 s 看不到板不开火"都是估值，没有用大量实测数据校准。

## 8. 给后来人的建议

- 改瞄准逻辑前先用 `--no-fire` 跟随观察，再开火。
- 改完先跑 `hero_test`，再上车。
- 注释写"为什么"，不写"是什么"；改了行为同步改注释和本文档。
