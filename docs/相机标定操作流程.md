# 相机标定：详细教程（小圆点板 + 大棋盘格）

本教程覆盖英雄相机的两步标定：先求内参（只要相机），再做手眼标定求相机安装外参（要开电控），结果写回 `configs/hero.yaml`。两块板（小圆点板、大棋盘格）都能用于两步。

命令从 `Heavy` 根目录执行。命令行选项采用 `--key=value`，避免 OpenCV 参数解析器把选项值解析成布尔量。

## 1. 区分三个概念

| 概念 | 回答的问题 | 常见结果 |
| --- | --- | --- |
| 内参标定 | 相机如何把空间点投影到像素？ | `K`、`D`、图像宽高 |
| 单张图片的板位姿 | 这一张图中，板相对相机在哪里？ | 每张图各自的 `R/t` |
| 手眼标定（handeye） | 相机与另一个刚体如何固定连接？ | 固定坐标变换及一致性指标 |

内参标定内部也会估计各图板位姿，但这不等于完成手眼标定。当前 `calibrate_camera` 只导出内参，不导出可直接使用的手眼结果。

## 2. 两张标定板：规格与打印

队里有两块板：小板 A 是白底黑圆点的对称圆点阵，大板 B 是棋盘格。两块板检测方式不同，配置里用 `pattern_type` 区分。

| 参数 | 小板 A（圆点） | 大板 B（棋盘格） |
| --- | --- | --- |
| `pattern_type` | `circles` | `chessboard` |
| 实物 | 7 × 7 个黑圆点 | **9 × 12 个方格**，板子最外缘不算 |
| 工具要数的点 | 7 × 7 = 49 个圆心 | **8 × 11 = 88 个中间交叉点**（内角点） |
| `pattern_cols` × `pattern_rows` | 7 × 7 | 11 × 8 |
| 间距字段 | `center_distance_mm: 25.0`（圆心距） | `square_size_mm: 35`（方格边长） |
| 首末特征点跨度 | `(7-1)×25 = 150 × 150 mm` | `(11-1)×35 = 350 mm` × `(8-1)×35 = 245 mm` |
| 配置 | `configs/calibration.yaml` | `configs/calibration_chessboard_11x8.yaml` |
| 打印文件 | [PDF](calibration_boards/circles_7x7_25mm_A4.pdf) / [SVG](calibration_boards/circles_7x7_25mm_A4.svg)，A4 | 已有实物板，无打印文件 |

**棋盘格数的是交叉点，不是格子。** 9 × 12 个方格只有 8 × 11 个中间交叉点；板子最外一圈边线（格子和白边的交界）不算交叉点。把 `pattern_cols/rows` 填成 12 × 9 会一直检测失败。

大板 B 与 ROS `camera_calibration` 是同一块板，ROS 写法为 `--size 11x8 --square 0.035`（`--size` 同样数内角点，`--square` 单位是米）。

小板 A 用 OpenCV `findCirclesGrid` + `CALIB_CB_SYMMETRIC_GRID`；大板 B 用 `findChessboardCornersSB`，自带亚像素精度，不读 `blob_*` 参数。

### 2.1 打印与实测

小板 A：

1. 下载 PDF，A4 竖向，选择“实际大小 / 100%”，关闭自适应、自动缩放和额外页眉页脚。
2. 量底部 100 mm 标尺，再量横竖方向多个圆心的总距离，例如跨 6 个间距应为 150 mm。
3. 多处检查横向和纵向，记录实测值。若存在非均匀缩放或纸张拉伸，重新打印。

大板 B：用尺量横竖多个方格的总长，例如跨 10 格应为 350 mm。实测不是 35 mm 时，在配置副本中改 `square_size_mm`。

两块板都要平整贴在刚性底板上，保持哑光、整洁、无折痕。

`center_distance_mm` 是圆心间距，不是圆直径；blob 面积以像素面积计量，与纸上的平方毫米不同。

小板便于近距离完整入画；大板便于在更远处保持足够的像素尺寸，具体取决于镜头视场。一次解算只使用一种板，两种板的图片不能混用。

## 3. 安装依赖与编译

Ubuntu 22.04 示例：

```bash
sudo apt-get update
sudo apt-get install -y \
  build-essential cmake git \
  libopencv-dev libeigen3-dev \
  libfmt-dev libspdlog-dev libyaml-cpp-dev \
  nlohmann-json3-dev

cmake -S . -B build/calibration \
  -DBUILD_HERO=OFF \
  -DBUILD_CALIBRATION=ON

cmake --build build/calibration -j4 --target calibrate_camera
./build/calibration/calibrate_camera --help
```

这里只构建内参目标，不打开外设。离线解算不需要 OpenVINO、ROS 或相机 SDK。

使用 `BUILD_HERO=OFF` 可只保留离线标定，给它单独使用 `build/calibration`，避免与其他构建目录的缓存混用。

## 4. 拍摄前准备

### 4.1 记录成像设置

在数据目录的 `notes.md` 记录：

- 相机型号、序列号和镜头型号。
- 图片宽高、ROI、像素合并、裁剪或缩放设置。
- 焦距、对焦位置和相关自动功能是否关闭。
- 板编号、点数、打印方式、实测圆心距或方格边长。
- 日期、操作者、图片数量和明显异常。

焦距、对焦或成像几何变化后应重新评估内参。仅改变曝光不会按比例改变内参，但过曝与模糊会降低圆心定位质量。

### 4.2 拍摄图片

用 `capture` 拍，不接电控时加 `--no-serial`，只存 `N.jpg`：

```bash
./build/capture datasets/intrinsic_chessboard/images --no-serial --board=configs/calibration_chessboard_11x8.yaml
```

它使用 `configs/hero.yaml` 的相机设置（分辨率、ROI、曝光），与自瞄运行时一致；按 `s` 保存、`a` 自动保存（板在画面中的位置或大小变化够大才存）、`q` 退出。也可以用厂商工具保存原始分辨率图片，但不要提前去畸变、透视矫正或缩放，不要使用桌面截图。

内参实验可保持相机固定，改变板的位置和方向。工具只需要图像与板几何，**不需要姿态 TXT、串口或 CAN**。

先采 20～30 张作为起点：

1. 完整板分别覆盖画面中心、左上、右上、左下、右下。
2. 改变远近，使板具有不同成像大小，同时保证全部圆点或全部 8 × 11 个交叉点清晰可见。
3. 增加绕不同方向的倾斜视角，避免全部正对相机。
4. 每次停稳再保存，删除模糊、反光、遮挡、缺点的图片。
5. 额外保留几张独立图片，后续检查使用，不参与拟合。

不要为了完整入画而缩小照片。应调整板的位置或距离，保留相机原始分辨率。

## 5. 整理文件与保存配置快照

### 5.1 小板 A

```bash
mkdir -p datasets/intrinsic_7x7/images
mkdir -p datasets/intrinsic_7x7/results
cp configs/calibration.yaml datasets/intrinsic_7x7/board.yaml
```

确认副本中的板参数：

```yaml
pattern_cols: 7
pattern_rows: 7
center_distance_mm: 25.0
blob_color: 0
```

`blob_color: 0` 表示黑色圆点；白色圆点才设为 `255`。使用本文模板时保持 `0`。

### 5.2 大板 B（棋盘格）

```bash
mkdir -p datasets/intrinsic_chessboard/images
mkdir -p datasets/intrinsic_chessboard/results
cp configs/calibration_chessboard_11x8.yaml datasets/intrinsic_chessboard/board.yaml
```

确认副本：

```yaml
pattern_type: chessboard
pattern_cols: 11      # 12 个方格 → 11 个内角点
pattern_rows: 8       # 9 个方格  → 8 个内角点
square_size_mm: 35    # 实测方格边长
```

### 5.3 输入文件规则

```text
images/
├── 1.jpg
├── 2.jpg
├── 3.jpg
└── ...
```

现有程序的约束：

- 从 `1.jpg` 开始，连续读取整数编号，不接受任意文件名列表。
- 遇到第一张不存在或无法解码的图片就停止，后面的图片不再检查。
- 内参不读取 `N.txt`；已有姿态文件不会影响内参结果。
- 所有图片必须同宽高；现有代码未显式拦截混合尺寸，需自行检查。
- 输出父目录需先创建；写文件辅助函数未完整检查写入错误，运行后应确认文件存在且非空。

如果软件导出 PNG，可用下面的通用脚本转换到一个**尚不存在的新目录**。它不修改源图，不缩放图片。需先安装 `python3-opencv`。

```bash
# 替换 raw_photos 为自己的原图目录。
# numbered_images 必须是尚不存在的新目录。
python3 - raw_photos numbered_images <<'PYTHON'
import sys
from pathlib import Path
import cv2

source, destination = map(Path, sys.argv[1:])
files = sorted(
    p for p in source.iterdir()
    if p.is_file() and p.suffix.lower() in {'.jpg', '.jpeg', '.png', '.bmp', '.tif', '.tiff'}
)
if not files:
    raise SystemExit('源目录没有支持的图片')
destination.mkdir(parents=True, exist_ok=False)
image_size = None
for index, path in enumerate(files, 1):
    image = cv2.imread(str(path))
    if image is None:
        raise SystemExit(f'无法读取：{path}')
    size = (image.shape[1], image.shape[0])
    if image_size is None:
        image_size = size
    if size != image_size:
        raise SystemExit(f'尺寸不一致：{path} 为 {size}，预期 {image_size}')
    output = destination / f'{index}.jpg'
    if not cv2.imwrite(str(output), image, [cv2.IMWRITE_JPEG_QUALITY, 100]):
        raise SystemExit(f'写入失败：{output}')
    print(f'{path.name} -> {output.name}')
print(f'完成：{len(files)} 张，宽高 {image_size}')
PYTHON
```

脚本异常退出可能留下部分结果。处理异常后换一个新目标目录重试。排序按文件名排序；重编号后仍需检查每张图片的内容和覆盖范围。

### 6.1 小板 A

```bash
./build/calibration/calibrate_camera datasets/intrinsic_7x7/images \
  --config-path=datasets/intrinsic_7x7/board.yaml \
  --camera-info=datasets/intrinsic_7x7/results/camera_info.yaml \
  --output=datasets/intrinsic_7x7/results/intrinsics_flat.yaml \
  --preview=none
```

### 6.2 大板 B（棋盘格）

```bash
./build/calibration/calibrate_camera datasets/intrinsic_chessboard/images \
  --config-path=datasets/intrinsic_chessboard/board.yaml \
  --camera-info=datasets/intrinsic_chessboard/results/camera_info.yaml \
  --output=datasets/intrinsic_chessboard/results/intrinsics_flat.yaml \
  --preview=none
```

启动时终端打印 `标定板 棋盘格(内角点) 11x8 @ 35.0mm`，用来确认读到的是棋盘格配置。

### 6.3 参数说明

| 参数 | 含义与注意事项 |
| --- | --- |
| 第一个位置参数 | 连续 `N.jpg` 的输入目录 |
| `--config-path=...` | 板与检测配置；默认 `configs/calibration.yaml` |
| `--camera-info=...` | ROS 风格内参 YAML 的**输出**；默认写 `configs/camera_info.yaml` |
| `--output=...` | 扁平内参输出；默认 `none`，不写此文件 |
| `--preview=none` | 不创建窗口，适合无显示器或 SSH |
| `--preview=auto` | 每张图短暂显示，需要图形环境 |
| `--preview=manual` | 每张按键后继续，不是交互剔除样本功能 |

显式传 `--camera-info=none` 可禁用这种文件输出，终端仍打印结果。每次实验指定独立输出路径，避免覆盖历史数据。

每张图打印 `[success]` 或 `[failure]`；失败图不参与拟合。工具不会按 `reproj_max_px` 自动剔除内参样本，该参数用于现有其他标定路径。

## 7. 理解输出

### 7.1 两种 YAML 格式

ROS 风格文件包含：

```yaml
image_width: 1440
image_height: 1080
camera_name: narrow_stereo
camera_matrix:
  rows: 3
  cols: 3
  data: [fx, 0, cx, 0, fy, cy, 0, 0, 1]
distortion_model: plumb_bob
distortion_coefficients:
  rows: 1
  cols: 5
  data: [k1, k2, p1, p2, k3]
```

上面使用符号占位，**不是可直接使用的数值配置**。1440×1080 只是示意，实际宽高来自图片。`camera_name` 由程序固定写成 `narrow_stereo`，不代表自动识别了相机型号。

扁平格式为：

```yaml
camera_matrix: [fx, 0, cx, 0, fy, cy, 0, 0, 1]
distort_coeffs: [k1, k2, p1, p2, k3]
```

矩阵按行展开。`fx/fy/cx/cy` 单位是像素，板圆心距和方格边长单位是毫米，畸变系数不以毫米为单位。当前求解固定 `k3`，不代表所有镜头都适合忽略更高阶畸变。

### 7.2 误差的含义

程序调用 `calibrateCamera` 并使用 `CALIB_FIX_K3`，随后自行计算：

```text
mean_error_px = Σ ||检测点 - 重投影点||₂ / 所有有效圆心或角点数量
```

这是欧氏距离的算术平均，不是 RMS。输出误差是 YAML 注释，不是独立机器可读字段。

经验上，小于约 0.3 px 是较好的初步信号，超过约 0.5 px 值得检查数据；这些数值受分辨率、镜头和图像质量影响，不是通用硬性验收线。

误差小也可能来自视角不足或照片过于相似，不能单凭它认定完成标定。当前程序未强制足够的样本数量，退出码为 0 不等于结果可靠。

## 8. 结果检查与问题排查

### 8.1 检查步骤

1. 确认实际读取图片数量符合预期，有足够多、覆盖充分的有效样本。
2. 打开两个结果文件，确认非空、宽高正确，没有 `nan` 或 `inf`。
3. 检查 `fx/fy` 为正、`K` 末行为 `[0,0,1]`，主点是否与成像裁剪方式相符。
4. 用未参与拟合的图片观察去畸变表现，检查边缘有无异常拉伸。
5. 独立重拍一批数据比较结果，而不只是重复拟合同一批照片。
6. 保留原图、配置快照、终端输出和结果，不要只留下两行参数。

单目内参的低误差不能证明板的物理尺度正确。圆心距或方格边长写错时 `K`、`D` 不受影响，但手眼标定的平移会按同一比例缩放，所以仍需实测。

### 8.2 检测参数

| 参数 | 作用 | 调整前检查 |
| --- | --- | --- |
| `pattern_type` | `circles` 或 `chessboard` | 与实物板一致 |
| `pattern_cols/rows` | 圆点列数和行数；棋盘格为内角点数 | 圆点数圆心；棋盘格 9×12 格填 11×8 |
| `center_distance_mm` | 相邻圆心距（圆点板） | 实测打印尺寸 |
| `square_size_mm` | 方格边长（棋盘格，必填） | 实测方格尺寸 |
| `blob_color` | 0 黑点，255 白点（仅圆点板） | 本文模板为黑点 |
| `blob_min_area/max_area` | 圆点像素面积范围 | 是否过滤了过远或过近的点 |
| `blob_min_circularity` | 圆形程度阈值 | 模糊、反光、过度倾斜 |
| `detect_scale` | 检测器预览缩放 | 离线内参始终全分辨率检测 |
| `reproj_max_px` | 其他标定路径的单帧阈值 | 不会自动筛除内参高误差图片 |

先检查规格、光照和清晰度，再调 blob。大幅放宽阈值可能引入背景假圆点。

### 8.3 常见故障

| 现象 | 原因与处理 |
| --- | --- |
| 无有效内参样本 | 检查路径、`1.jpg`、图片是否可读、板规格 |
| 提前停止读取 | 编号断档或文件损坏，在新目录整理连续编号 |
| 一直检测失败 | 检查 `pattern_type`、点数与黑白方向；棋盘格填的是内角点 11×8，不是方格 12×9 |
| 棋盘格偶尔失败 | 板子要完整入画，避免强反光和过大倾角 |
| 显示已保存但结果为空/缺失 | 创建输出父目录，检查写权限与文件内容 |
| 无法连接显示 | 使用 `--preview=none` |
| 参数像布尔值 `true` | 使用 `--参数=值` |
| 参数波动明显 | 固定成像设置，检查板平整度，增加多样视角 |

## 9. 手眼标定（英雄实车）

手眼标定求相机相对云台的安装关系 `R_camera2gimbal`、`t_camera2gimbal`，结果直接写进 `configs/hero.yaml`。它需要每张照片配一组拍摄时的云台姿态，所以**采集时必须开电控**，由电控通过串口 0x5A 反馈帧回传 yaw/pitch。求解是离线的，不需要电控。

### 9.1 前提

- 已完成第 6 节的内参标定，并把 `camera_matrix`、`distort_coeffs` 写进 `configs/hero.yaml`。`capture` 会把 `hero.yaml` 里的内参复制进数据目录，求解时用的就是这一份。
- 云台轴偏置 `p_yaw_to_pitch_mm`（yaw 轴中心到 pitch 轴中心，X 前 Y 左 Z 上）已经填进板配置。两个板配置里现在都是英雄的 `[62.11, 0, 151.32]` mm，换车要改。
- 已编译完整工程（`build/capture` 需要相机和串口，只在 `BUILD_HERO=ON` 时生成）。

### 9.2 采集

1. 把标定板**竖直**固定在云台正前方：大棋盘格约 2～3 m，小圆点板约 1～1.5 m。采集过程中板子绝对不能动。
2. 电控上电，确认串口在发反馈。云台由遥控器或电控手动控制，`capture` 只读串口，不发任何控制帧。
3. 运行：

```bash
./build/capture datasets/handeye_$(date +%m%d_%H%M) --board=configs/calibration_chessboard_11x8.yaml
# 小圆点板：--board=configs/calibration.yaml
```

窗口按键：`s` 保存当前帧，`a` 切换自动保存，`q` 退出。SSH 没有显示时加 `--preview=none`，这时自动保存，按 Ctrl+C 结束。终端每秒打印一行状态：

```text
相机 165 FPS  检测 47 FPS  板 检出  姿态 yaw 3.12° pitch 1.05° 50ms转角 0.004°  已存 7  自动 开  → 可保存
```

只有三项条件同时满足才会保存，否则打印原因：

| 条件 | 不满足时的提示 | 处理 |
| --- | --- | --- |
| 全分辨率完整检出标定板 | `未完整检出标定板` | 板子全部入画，避免反光；核对 `--board` |
| 有串口姿态 | `串口姿态超时或缺失` | 电控是否上电、是否在发 0x5A、串口设备和权限 |
| 云台静止（图像前 50 ms 转角 < `--still-deg`，默认 0.05°） | `云台未静止` | 转到位后停稳再保存 |

4. 转云台：yaw 和 pitch 都要转，板子要一直留在画面里。英雄相机视场约 23°×17°，所以 yaw 只能在约 ±5°、pitch 约 ±4° 内覆盖。建议按网格走：yaw 取 5 档、pitch 取 4 档，存 15～25 张。自动模式下，与已存样本的 yaw/pitch 差小于 `--min-angle`（默认 2°）的姿态不会重复保存。

输出目录里是 `1.jpg`、`1.txt`……和 `board.yaml`。`N.txt` 是一行 `w x y z` 四元数，即按图像时间戳插值出的云台姿态，与 `build/hero` 运行时给 Solver 的姿态是同一个（yaw 绕 +Z，pitch 抬头为正）。`capture` 不会清空已有目录；目录里已有图片时报错，需要续拍就加 `--append`。

### 9.3 求解

```bash
D=datasets/handeye_1109_2130   # 换成自己的目录
./build/calibrate_robotworld_handeye $D --config-path=$D/board.yaml --output=$D/result.yaml --preview=none
./build/calibrate_handeye            $D --config-path=$D/board.yaml --output=$D/result_handeye.yaml --preview=none
```

- `calibrate_robotworld_handeye` 是主路径：同时解相机外参和板在世界中的位置，用到云台轴偏置。
- `calibrate_handeye` 用来交叉对照，默认方法 `--method=park`。**不要用 `tsai`**：英雄只能小角度转动，TSAI 会判定“运动不足”，返回错误结果却不报错退出（旧代码就是这样）。
- 两者结果应相差在 0.1° 和几毫米以内，差得多说明数据有问题。

终端最后打印：

```text
链路重投影（板→世界→云台→相机→像素）: 平均 0.4 px，最差一张 0.9 px (.../12.jpg)
```

这是判断结果能不能用的主要指标：把固定不动的板经“世界 → 云台（串口姿态 + 轴偏置）→ 相机（标定结果）”投回每张图，与检测点比较。经验上平均 < 1 px 可用；> 3 px 多半是姿态没同步、轴偏置不对或板子被碰动，看“最差一张”是哪张。

### 9.4 写回配置

`result.yaml` 里的三项一起替换进 `configs/hero.yaml`：

```yaml
R_camera2gimbal: [...]   # OpenCV 相机系到云台，直接给 Solver
t_camera2gimbal: [...]   # 米
camera_rpy: [r, p, y]    # 弧度，URDF 相机本体约定，与 ROS2 分支 launch_params 的 rpy 相同
```

只替换 R、不替换 `camera_rpy` 会让两者不一致。替换后用 `./build/hero --no-fire --show` 看重投影的绿框是否贴合装甲板，再上车验证。

### 9.5 实现说明

- 采集：相机由主线程读取，预览检测在后台线程只处理最新一帧且降采样，保存时才做全分辨率复检，所以相机保持满帧（实测 165 FPS）。旧 ROS `capture_node` 每 30 ms 在 ROS 回调里新建检测器、做全分辨率检测，会阻塞图像订阅；姿态取“最近一次关节角”，没有按时间对齐；启动时还会清空输出目录；默认 11×8 却用圆点检测，识别不了棋盘格。
- 求解：多线程检测全部图片，不再每张 `waitKey(500)`。读姿态时检查四元数是否缺失、能否解析、是否归一化。
- 两套求解器都用竖直板模型（原点在板心，Y 向右、Z 向上），与内参的平面板模型不同；板的点序 180° 歧义按前后帧距离对齐。
- 回归测试 `tests/calibration/handeye_calibration_test.cpp`：用 `configs/hero.yaml` 的外参和真实轴偏置渲染 20 组姿态，两个求解器、两种板都必须还原外参（旋转 < 0.05°、平移 < 2 mm、`camera_rpy` < 0.001 rad）。当前结果为旋转 0.003～0.006°、平移 0.1～0.3 mm。

## 10. 每次实验保留什么

```text
一次独立实验/
├── notes.md                  相机、镜头、成像设置、板实测尺寸
├── board.yaml                本次检测配置快照
├── images/                   连续编号标定图片（手眼另有同编号 N.txt）
├── holdout/                  未参与拟合的检查图片
└── results/
    ├── camera_info.yaml      内参及尺寸
    ├── intrinsics_flat.yaml  扁平内参
    ├── result.yaml           手眼结果（R_camera2gimbal、t_camera2gimbal、camera_rpy）
    └── terminal.txt          本次终端输出（手动保存）
```

换板、镜头、焦距或分辨率时新建实验目录。结果文件不会自动修改其他任务配置；把原始数据与结果一起留存才能复查。
