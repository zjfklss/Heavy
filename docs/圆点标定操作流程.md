# 圆点板相机标定：详细教程

本教程适用于独立的成像与几何测量实验：选择标定板、拍摄数据、离线求内参、保存和检查结果，并理解通用 handeye 的数据约定。本文不提供该发射平台的实机手眼标定、瞄准外参接入或射击操作。

命令从 `Heavy` 根目录执行。命令行选项采用 `--key=value`，避免 OpenCV 参数解析器把选项值解析成布尔量。

## 1. 区分三个概念

| 概念 | 回答的问题 | 常见结果 |
| --- | --- | --- |
| 内参标定 | 相机如何把空间点投影到像素？ | `K`、`D`、图像宽高 |
| 单张图片的板位姿 | 这一张图中，板相对相机在哪里？ | 每张图各自的 `R/t` |
| 手眼标定（handeye） | 相机与另一个刚体如何固定连接？ | 固定坐标变换及一致性指标 |

内参标定内部也会估计各图板位姿，但这不等于完成手眼标定。当前 `calibrate_camera` 只导出内参，不导出可直接使用的手眼结果。

## 2. 两张标定板：规格与打印

“两张”指仓库已有配置对应的两种板。手中实物若不同，应先实测并复制配置修改，不能仅凭外观选文件。

| 参数 | 小板 A | 大板 B |
| --- | --- | --- |
| `pattern_cols` | 7 | 10 |
| `pattern_rows` | 7 | 7 |
| 圆点总数 | 49 | 70 |
| `center_distance_mm` | 25.0 | 40.0 |
| 首末圆心水平跨度 | `(7-1)×25 = 150 mm` | `(10-1)×40 = 360 mm` |
| 首末圆心竖直跨度 | `(7-1)×25 = 150 mm` | `(7-1)×40 = 240 mm` |
| 本次模板圆直径 | 12.5 mm | 20 mm |
| 模板纸张 | A4，210×297 mm | A2 横向，594×420 mm |
| 配置 | `configs/calibration.yaml` | `configs/calibration_10x7.yaml` |
| PDF | [小板 A](calibration_boards/circles_7x7_25mm_A4.pdf) | [大板 B](calibration_boards/circles_10x7_40mm_A2.pdf) |
| SVG | [小板 A](calibration_boards/circles_7x7_25mm_A4.svg) | [大板 B](calibration_boards/circles_10x7_40mm_A2.svg) |

两种板都使用 OpenCV `CALIB_CB_SYMMETRIC_GRID`，每列圆心上下对齐。棋盘格、错列圆点阵、ChArUco 板不能套用这些配置。

### 2.1 打印与实测

1. 下载 PDF，选择匹配的纸张和方向。
2. 选择“实际大小 / 100%”，关闭自适应、自动缩放和额外页眉页脚。
3. 大板交给支持 A2 的设备，不能缩小到 A4；不建议未校验地拼接多张纸。
4. 量底部 100 mm 标尺，再量横竖方向多个圆心的总距离。例如小板跨 6 个间距应为 150 mm。
5. 多处检查横向和纵向，记录实测值。若存在非均匀缩放或纸张拉伸，重新打印。
6. 平整贴到刚性底板上，保持哑光、整洁、无折痕。

`center_distance_mm` 是圆心间距，不是圆直径。模板圆直径是本次绘图选择，检测配置的 blob 面积则以像素面积计量，与纸上的平方毫米不同。

小板便于近距离完整入画，大板便于在更远处保持圆点像素大小，具体取决于镜头视场。一次解算只使用一种板，两种板的图片不能混用。

## 3. 安装依赖与编译

Ubuntu 22.04 示例：

```bash
sudo apt-get update
sudo apt-get install -y \
  build-essential cmake git \
  libopencv-dev libeigen3-dev \
  libfmt-dev libspdlog-dev libyaml-cpp-dev \
  nlohmann-json3-dev

cmake -S . -B build/calibration \
  -DBUILD_HERO=OFF \
  -DBUILD_CALIBRATION=ON

cmake --build build/calibration -j4 --target calibrate_camera
./build/calibration/calibrate_camera --help
```

这里只构建内参目标，不打开外设。离线解算不需要 OpenVINO、ROS 或相机 SDK。

使用 `BUILD_HERO=OFF` 可只保留离线标定，给它单独使用 `build/calibration`，避免与其他构建目录的缓存混用。

## 4. 拍摄前准备

### 4.1 记录成像设置

在数据目录的 `notes.md` 记录：

- 相机型号、序列号和镜头型号。
- 图片宽高、ROI、像素合并、裁剪或缩放设置。
- 焦距、对焦位置和相关自动功能是否关闭。
- 板编号、点数、打印方式、实测圆心距。
- 日期、操作者、图片数量和明显异常。

焦距、对焦或成像几何变化后应重新评估内参。仅改变曝光不会按比例改变内参，但过曝与模糊会降低圆心定位质量。

### 4.2 拍摄图片

使用厂商工具或独立采集软件保存原始分辨率图片。不要提前去畸变、透视矫正或任意缩放，不要使用桌面截图。

内参实验可保持相机固定，改变板的位置和方向。工具只需要图像与板几何，**不需要姿态 TXT、串口或 CAN**。

先采 20～30 张作为起点：

1. 完整板分别覆盖画面中心、左上、右上、左下、右下。
2. 改变远近，使板具有不同成像大小，同时保证全部圆点清晰可见。
3. 增加绕不同方向的倾斜视角，避免全部正对相机。
4. 每次停稳再保存，删除模糊、反光、遮挡、缺点的图片。
5. 额外保留几张独立图片，后续检查使用，不参与拟合。

不要为了完整入画而缩小照片。应调整板的位置或距离，保留相机原始分辨率。

### 5.3 输入文件规则

```text
images/
├── 1.jpg
├── 2.jpg
├── 3.jpg
└── ...
```

现有程序的约束：

- 从 `1.jpg` 开始，连续读取整数编号，不接受任意文件名列表。
- 遇到第一张不存在或无法解码的图片就停止，后面的图片不再检查。
- 内参不读取 `N.txt`；已有姿态文件不会影响内参结果。
- 所有图片必须同宽高；现有代码未显式拦截混合尺寸，需自行检查。
- 输出父目录需先创建；写文件辅助函数未完整检查写入错误，运行后应确认文件存在且非空。

如果软件导出 PNG，可用下面的通用脚本转换到一个**尚不存在的新目录**。它不修改源图，不缩放图片。需先安装 `python3-opencv`。

```bash
# 替换 raw_photos 为自己的原图目录。
# numbered_images 必须是尚不存在的新目录。
python3 - raw_photos numbered_images <<'PYTHON'
import sys
from pathlib import Path
import cv2

source, destination = map(Path, sys.argv[1:])
files = sorted(
    p for p in source.iterdir()
    if p.is_file() and p.suffix.lower() in {'.jpg', '.jpeg', '.png', '.bmp', '.tif', '.tiff'}
)
if not files:
    raise SystemExit('源目录没有支持的图片')
destination.mkdir(parents=True, exist_ok=False)
image_size = None
for index, path in enumerate(files, 1):
    image = cv2.imread(str(path))
    if image is None:
        raise SystemExit(f'无法读取：{path}')
    size = (image.shape[1], image.shape[0])
    if image_size is None:
        image_size = size
    if size != image_size:
        raise SystemExit(f'尺寸不一致：{path} 为 {size}，预期 {image_size}')
    output = destination / f'{index}.jpg'
    if not cv2.imwrite(str(output), image, [cv2.IMWRITE_JPEG_QUALITY, 100]):
        raise SystemExit(f'写入失败：{output}')
    print(f'{path.name} -> {output.name}')
print(f'完成：{len(files)} 张，宽高 {image_size}')
PYTHON
```

脚本异常退出可能留下部分结果。处理异常后换一个新目标目录重试。排序按文件名排序；重编号后仍需检查每张图片的内容和覆盖范围。

## 6. 离线内参解算

### 6.1 小板 A

```bash
./build/calibration/calibrate_camera datasets/intrinsic_7x7/images \
  --config-path=datasets/intrinsic_7x7/board.yaml \
  --camera-info=datasets/intrinsic_7x7/results/camera_info.yaml \
  --output=datasets/intrinsic_7x7/results/intrinsics_flat.yaml \
  --preview=none
```

### 6.2 大板 B

```bash
./build/calibration/calibrate_camera datasets/intrinsic_10x7/images \
  --config-path=datasets/intrinsic_10x7/board.yaml \
  --camera-info=datasets/intrinsic_10x7/results/camera_info.yaml \
  --output=datasets/intrinsic_10x7/results/intrinsics_flat.yaml \
  --preview=none
```

### 6.3 参数说明

| 参数 | 含义与注意事项 |
| --- | --- |
| 第一个位置参数 | 连续 `N.jpg` 的输入目录 |
| `--config-path=...` | 板与检测配置；默认 `configs/calibration.yaml` |
| `--camera-info=...` | ROS 风格内参 YAML 的**输出**；默认写 `configs/camera_info.yaml` |
| `--output=...` | 扁平内参输出；默认 `none`，不写此文件 |
| `--preview=none` | 不创建窗口，适合无显示器或 SSH |
| `--preview=auto` | 每张图短暂显示，需要图形环境 |
| `--preview=manual` | 每张按键后继续，不是交互剔除样本功能 |

显式传 `--camera-info=none` 可禁用这种文件输出，终端仍打印结果。每次实验指定独立输出路径，避免覆盖历史数据。

每张图打印 `[success]` 或 `[failure]`；失败图不参与拟合。工具不会按 `reproj_max_px` 自动剔除内参样本，该参数用于现有其他标定路径。

## 7. 理解输出

### 7.1 两种 YAML 格式

ROS 风格文件包含：

```yaml
image_width: 1440
image_height: 1080
camera_name: narrow_stereo
camera_matrix:
  rows: 3
  cols: 3
  data: [fx, 0, cx, 0, fy, cy, 0, 0, 1]
distortion_model: plumb_bob
distortion_coefficients:
  rows: 1
  cols: 5
  data: [k1, k2, p1, p2, k3]
```

上面使用符号占位，**不是可直接使用的数值配置**。1440×1080 只是示意，实际宽高来自图片。`camera_name` 由程序固定写成 `narrow_stereo`，不代表自动识别了相机型号。

扁平格式为：

```yaml
camera_matrix: [fx, 0, cx, 0, fy, cy, 0, 0, 1]
distort_coeffs: [k1, k2, p1, p2, k3]
```

矩阵按行展开。`fx/fy/cx/cy` 单位是像素，板圆心距单位是毫米，畸变系数不以毫米为单位。当前求解固定 `k3`，不代表所有镜头都适合忽略更高阶畸变。

### 7.2 误差的含义

程序调用 `calibrateCamera` 并使用 `CALIB_FIX_K3`，随后自行计算：

```text
mean_error_px = Σ ||检测圆心 - 重投影圆心||₂ / 所有有效圆点数量
```

这是欧氏距离的算术平均，不是 RMS。输出误差是 YAML 注释，不是独立机器可读字段。

经验上，小于约 0.3 px 是较好的初步信号，超过约 0.5 px 值得检查数据；这些数值受分辨率、镜头和图像质量影响，不是通用硬性验收线。

误差小也可能来自视角不足或照片过于相似，不能单凭它认定完成标定。当前程序未强制足够的样本数量，退出码为 0 不等于结果可靠。

## 8. 结果检查与问题排查

### 8.1 检查步骤

1. 确认实际读取图片数量符合预期，有足够多、覆盖充分的有效样本。
2. 打开两个结果文件，确认非空、宽高正确，没有 `nan` 或 `inf`。
3. 检查 `fx/fy` 为正、`K` 末行为 `[0,0,1]`，主点是否与成像裁剪方式相符。
4. 用未参与拟合的图片观察去畸变表现，检查边缘有无异常拉伸。
5. 独立重拍一批数据比较结果，而不只是重复拟合同一批照片。
6. 保留原图、配置快照、终端输出和结果，不要只留下两行参数。

单目内参的低误差不能证明板的物理尺度正确，实际圆心距仍需测量，尤其是之后涉及尺度测量时。

### 8.2 检测参数

| 参数 | 作用 | 调整前检查 |
| --- | --- | --- |
| `pattern_cols/rows` | 圆点列数和行数 | 数圆心，不是间隔 |
| `center_distance_mm` | 相邻圆心距 | 实测打印尺寸 |
| `blob_color` | 0 黑点，255 白点 | 本文模板为黑点 |
| `blob_min_area/max_area` | 圆点像素面积范围 | 是否过滤了过远或过近的点 |
| `blob_min_circularity` | 圆形程度阈值 | 模糊、反光、过度倾斜 |
| `detect_scale` | 检测器预览缩放 | 离线内参始终全分辨率检测 |
| `reproj_max_px` | 其他标定路径的单帧阈值 | 不会自动筛除内参高误差图片 |

先检查规格、光照和清晰度，再调 blob。大幅放宽阈值可能引入背景假圆点。

### 8.3 常见故障

| 现象 | 原因与处理 |
| --- | --- |
| 无有效内参样本 | 检查路径、`1.jpg`、图片是否可读、板规格 |
| 提前停止读取 | 编号断档或文件损坏，在新目录整理连续编号 |
| 一直检测失败 | 检查对称阵类型、点数与黑白方向 |
| 显示已保存但结果为空/缺失 | 创建输出父目录，检查写权限与文件内容 |
| 无法连接显示 | 使用 `--preview=none` |
| 参数像布尔值 `true` | 使用 `--参数=值` |
| 参数波动明显 | 固定成像设置，检查板平整度，增加多样视角 |

## 9. handeye：通用原理与数据约定

本节帮助理解通用机器人视觉中的 handeye，不提供该发射平台的实机操作、解算命令或外参接入步骤。

### 9.1 固定关系和方程

- **Eye-in-hand**：相机固定在机器人运动端，相机与运动端的变换固定。
- **Eye-to-hand**：相机固定在环境中，机器人相对相机运动，不能直接照搬前一种变换链。
- **Robot-world / hand-eye 联合标定**：同时估计两组坐标关系，输入语义和求解假设不同。

通用相对运动方程常写成 `A X = X B`，联合问题常写为 `A X = Z B`。这些只表达约束形式；各符号的坐标系、方向、是否取逆，取决于明确定义的变换链。

### 9.2 变换方向

可用 `T_A_from_B` 表示“将 B 坐标中的点变到 A 坐标”：

```text
p_A = R_A_from_B · p_B + t_A_from_B

T_A_from_B = [ R  t ]
             [ 0  1 ]

T_B_from_A = [ Rᵀ  -Rᵀt ]
             [ 0      1  ]
```

求逆不能只把平移改成负号，矩阵乘法顺序不能任意交换。OpenCV 光学系通常 X 向右、Y 向下、Z 向前；其他坐标系需单独定义。

### 9.3 数据需要说明什么

独立的通用手眼实验应记录：

- 图片采集时间、分辨率及内参版本。
- 位姿时间、源坐标系、目标坐标系和长度单位。
- 姿态表达方式；若用欧拉角，还需明确轴与旋转顺序。
- 四元数分量顺序、有效性和归一化约定。
- 板规格，以及实验中哪些刚体固定、哪些运动。

“编号相同”不代表已经同步，接收时间不一定是曝光时刻。单一方向或变化很小的运动可能导致参数不可辨识，需在通用实验设计中评估可观测性。

### 9.4 现有实现的阅读提示

现有 `calibrate_handeye.cpp` 和 `calibrate_robotworld_handeye.cpp` 共用 `calib_common.hpp`：

- 图片沿用 `N.jpg`，配对姿态为 `N.txt`。
- `read_q` 按 `w x y z` 读取，不能直接替换成 `x y z w`。
- 读取辅助函数未完整检查读文件失败或四元数有效性；程序启动成功不代表数据有效。
- 内参使用平面板模型，两套现有手眼使用竖直板模型，板坐标定义不同。
- 实现包含该平台的轴与安装假设，不是任意机器人通用求解器。
- 对称阵有点序歧义；当前按前后点序距离反转的辅助逻辑是启发式处理，不是唯一编码识别。
- 不同设备的历史参考外参不能确认当前设备的固定坐标关系。

通用结果检查关注旋转正交性、行列式、变换链闭环残差及独立数据一致性。单张 PnP 误差小不能单独证明手眼正确。

## 10. 每次实验保留什么

```text
一次独立实验/
├── notes.md                  相机、镜头、成像设置、板实测尺寸
├── board.yaml                本次检测配置快照
├── images/                   连续编号标定图片
├── holdout/                  未参与拟合的检查图片
└── results/
    ├── camera_info.yaml      内参及尺寸
    ├── intrinsics_flat.yaml  扁平内参
    └── terminal.txt          本次终端输出（手动保存）
```

换板、镜头、焦距或分辨率时新建实验目录。结果文件不会自动修改其他任务配置；把原始数据与结果一起留存才能复查。
