# 修改说明

相对开源 ITL 和本队 `hero_lidar_lob_shot` 的差异。产品代码只在 `/home/jlcv/heavy/src/heavy_lob_shot_manager`。

## 相对 ITL（vendor 对照包）

1. **ITL 弹道/瞄准整包复制。** `src/projectile_motion`、`src/lob_shot_aiming` 从 ITL `Real/src/control` 原样拷入再补丁。`vendor/itl_control` 仍是只读原文。不编 ITL `lob_shot_manager`（`utils` 日志 + `JointState`）。
2. **坐标系。** ITL：`map → chassis → muzzle`。本队 NUDT：`map → base_link`。`LobShotAiming` 的 chassis 参数传入 `base_link`。静态 TF `base_link → muzzle` 写在 yaml，不改 NUDT URDF。
3. **弹道初值。** ITL `solve()` 从 `atan2(h, x)` 起步，落到平射支。本队在同一套 ITL 迭代循环上加了 `solve_high`：真空高抛根 `(v² + √Δ)` 作 `aimed_h` 初值。`friction≈0` 时 GAF 前向退化为真空抛物线，避免 ITL 的 `exp(k·x)/k` 爆炸。manager 再按 `pitch_max_deg`（默认 42）选支：高抛能打就高抛，超限才用平射；两支都超则 inhibit。不要把解本身截成 42°——中间角打不中。
4. **云台出口。** ITL 发 `JointState`。本队发 `geometry_msgs/Vector3` 到 `/gimbal_command`：`x=pitch`，`y=yaw`，`z=0/1/2`，由现有 `jlcv_serial_driver` 打成 `0xA5`。
5. **开火。** ITL 的 READY 只发 `ready_to_shoot`。本队 READY 时 `z=1` 保持瞄准；只有 `/lob_shot/fire` 为 true 才 `z=2`。
6. **空闲不抢云台。** IDLE / 模块未就绪时**不发布** `/gimbal_command`。持续发 `z=0` 会和自瞄抢串口。
7. **重装门闩。** 未解锁 / 未对接 / 装配中：状态 `INHIBITED`，不发云台。ITL 无此门闩。
8. **干跑反馈。** 静态 TF 不会跟着指令动。`feedback_mode:=open_loop` 时解完 yaw/pitch 即视为收敛，用来把状态机跑到 READY。实车用 `joint_state`，吃串口驱动发的 `/joint_states`（`pitch_joint` / `yaw_joint`）。
9. **执行。** 默认按 ITL `Simulation_shoot`：`itl_shoot.launch.py`（manager + RViz + 栅格），不跑 Gazebo。ITL Fortress / PolarBear 整场仿真不编、不当默认入口。

## 相对本队 hero_lidar_lob_shot

## 主吊射站位（梯形高地旁 +200 mm 小平面）

真正目标不变：打蓝方中间偏平大装甲。改的是**射手站位**，不是靶。
