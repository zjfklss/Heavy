## 使用

UI 点击“打开配置”，选择对应 JSON；相机页查看内参，云台的安装页查看外参。
也可从仿真项目根目录启动：

```bash
./start_simulation.sh --config configs/scenarios/sensors/infantry3.json
```

需要连接自瞄时，先独立启动**对应兵种 YAML** 的自瞄进程，再在 UI“调度 → 算法”将控制器切到
“外部自瞄”，协议选 SP Vision；默认地址 `127.0.0.1:17001`。例如已构建的 infantry3 自瞄：

```bash
build/sp-vision/jlcv /home/jlcv/sp_vision_jlcv/configs/jlcv/infantry3.yaml --simulation=true
```

infantry4、sentry 替换为对应 YAML。也可用 `scripts/start_sp_vision.sh --robot=infantry3 --simulation`
自动选择 `configs/jlcv/simulation/infantry3.yaml` 并打开对应 JSON 的仿真；默认兵种为 infantry4。
不传 `--simulation` 时脚本使用 `configs/jlcv/` 下同兵种 YAML，以实机模式运行。
相机配置中的标识区分传感器/标定版本，不会自动替外部程序选择兵种算法配置。
SP 握手仍使用仿真标定和无畸变参数，其他算法阈值、瞄准偏置沿用外部进程所选 YAML。

## 原始参数中尚未模拟的部分

当前成像器是无畸变针孔模型。下列畸变系数为来源原值，**仅在此保存，不作用于当前图像**；
没有向运行 JSON 填入程序不支持的字段。

| 配置 | 原始 D = [k1, k2, p1, p2, k3] |
| --- | --- |
| infantry3 | `[-0.077821, 0.197339, -0.002876, -0.002177, 0]` |

三套原配置共同的相机参数：海康、曝光 0.8 ms、增益 16、ROI 偏移 `[0,0]`、关闭外部触发、
开启帧率控制。这些硬件设置暂不影响合成相机，没有模拟曝光积分、增益响应或运动模糊。
原 `R_gimbal2imubody` 均为单位阵；当前反馈直接提供云台姿态，没有单独的 IMU 原始采样模型。
原串口 `timestamp_offset=0.0065` s 是实机时间对齐参数，不等同于观测或反馈延迟，因此没有将其填成 6.5 ms 模拟延迟。

后续更新实机 YAML 后，需要同步更新相应 JSON 和本说明；这些文件是本次参数快照，不会隐式读取工程外的配置。
