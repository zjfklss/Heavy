# 实时仿真与自瞄联调

UI 直接显示正在运行的世界状态和相机像素。顶部标签为“目标、相机、云台、调度、监测”；
进度条、播放、单帧、复位和倍速控件已移除。

## 启动和停止

终端一启动独立自瞄：

```bash
/home/jlcv/rm_simulation/build/sp-vision/jlcv \
  /home/jlcv/sp_vision_jlcv/configs/jlcv/simulation/infantry4.yaml --simulation=true --sim-ui=false --show=true
```

终端二启动 UI：

```bash
/home/jlcv/rm_simulation/start_simulation.sh \
  --config /home/jlcv/rm_simulation/configs/scenarios/adapters/sp_vision.json
```

UI 自动开始实时运行，持续到“停止”或关闭窗口。`scene.duration` 仅安排已有预置事件/发弹，
并供 CLI 批处理校验，不会让实时会话自动结束。监测页显示当前状态和最近命中。
实时模式允许自瞄尚未启动、关闭修改代码或通信超时：世界和相机继续运行，状态栏显示“等待自瞄连接”，不弹出断线错误。
后台每隔 0.5 秒重试连接，自瞄重新监听后自动建立新会话，世界时间与统计不重置。
断线时清除尚未交付的控制和旧 telemetry；重连后使用当前图像、反馈，并按新会话区分发弹请求 ID。
已经进入执行器队列的指令继续按原时序执行；非法报文、版本或会话不匹配仍终止运行并报错。
三维画面左上角以无背景、无边框的一行小字显示准确率和 DPS。
准确率为本轮累计有效命中数 / 已发射弹丸数，尚未发射时显示“—”；飞行中的弹丸已计入发射数，落靶后才可能计入有效命中。
DPS 按每次有效命中 20 点伤害计算，为最近 5 秒伤害总量 / 5 秒；启动不足 5 秒时也使用 5 秒作为分母。每次重新运行时清零。
“应用并重启”用修改后的配置开始新会话；独立自瞄继续接受下一次连接。
正常停止发送结束握手，无法及时应答时 UI 终止后端，避免阻塞界面。

infantry3、infantry4、sentry 相机预设在 `configs/scenarios/sensors/`，默认不使用算法；
连接自瞄时在“调度 → 算法”选择外部自瞄及 SP Vision 协议。

## 时间和线程

- 世界与执行器按 `steady_clock` 经过时间推进固定物理 tick，正常速率为 1×。
- 相机渲染在独立线程完成，仅有一个待渲染任务和一个待交付结果；处理落后时替换旧任务。
- 图像使用采样时刻的世界和实际相机位姿。`capture_time` 保留采样时间，`ready_time` 包括实际生成完成时间及配置延迟。
- 自瞄 TCP 仍逐条请求/应答，但使用另一线程；处理慢时下一次发送最新图像和有界的反馈历史。
- 返回指令在收到后进入当前执行器队列，至少下一 tick 生效；配置的命令/发射延迟继续作用。
- UI 用本地二进制帧流接收状态和 BGR8 像素，约 30 Hz 更新，不等待最终 JSON，也不使用 PNG 传递实时画面。

60/165 Hz 是期望采样率，实际输出由生成能力决定。过载时丢旧帧，保持世界时间和当前画面；
底部显示实际相机输出率、设定率、实际 GPU/CPU 后端、“渲染丢弃”和外部自瞄的“待发丢弃”。
前者是相机队列过载，后者是等待自瞄处理时旧图被最新图替换；两者独立统计。采样率不等于算法处理率，仍无硬实时保证。
UI 只保留最多 90 个最近显示状态用于轨迹线，监测列表显示最近 128 条接触事件，不保留整个运行视频。
板上的小绿点表示弹丸接触位置，附着在对应装甲板上，随板移动、旋转并在 5 秒后消失；
板背面及其他几何会遮挡标记。有效性及未计分原因仍在监测列表中显示。
实时流保留最近 5 秒的全部接触及至少最近 128 条事件，避免高射速时标记提前被挤掉。
接触记录 `point` 保留碰撞时的世界坐标，新增 `plate_point` 为板面 right/up/normal 基底中的局部坐标（m）。
这些字段只用于评估和显示，不进入相机图像或算法输入。旧离线轨迹缺少局部坐标时，按最近记录帧近似恢复附着点。

`hello.configuration.realtime=true`、`duration=null` 表示持续实时会话，其余 `rm-sim/1` 格式兼容。
SP 输入入口把模拟秒映射到本地 `steady_clock`，调用已有实时 Aimer 时钟模式；批处理仍使用逻辑时钟。
已到达且有对应反馈的延迟图像不会仅因超过等待反馈时间而被错误丢弃。算法本体没有迁入仿真或改写。

本地显示帧为 `RML1` + JSON/像素长度（两个网络字节序 uint32），后接 JSON 和连续 BGR8。
显示状态含评估世界信息，仅送 UI；自瞄套接字仍只有传感器及名义标定，不含评估真值。

## 导出与验证

原 CLI 批处理导出供生成轨迹和回归验证，正常 UI 使用 `rm_sim_loop --live 配置.json`。
`--live-for=秒数` 仅用于有时限的自动验证，正常 UI 不传此参数。
原轨迹文件参数仅供读取最后状态及兼容测试，不提供播放控件。

`tests/protocol/live_test.py` 检查首帧提前到达、持续超过配置时长、墙钟一致性、慢自瞄不阻塞世界和画面、
控制实际作用、停止握手、无 PNG 归档和 UI 控件移除。
`tests/protocol/live_reconnect_test.py` 检查无自瞄启动、关闭和重启独立自瞄进程、自动恢复控制、跨会话发弹 ID、
断线停止及 Qt 等待状态，并确认错误协议仍被拒绝。
`tests/protocol/sp_vision_test.py` 验证真实独立 SP 与实时 UI 的收发及再次连接。

## GPU 与原生分辨率相机

`sensor.image.renderer` 可选 `auto`（默认，优先硬件 GPU）、`gpu`（必须有硬件 GPU）或 `cpu`。
也可在 UI“相机 → 成像 → 渲染后端”选择。实际后端显示在相机标题和状态栏，设备名称在相机画面的提示中。
`auto` 无可用硬件时明确记录原因并回退 CPU；`gpu` 不可用会报错。llvmpipe/softpipe 等软件 OpenGL 不作为硬件 GPU。

GPU 使用 EGL 设备离屏上下文和 OpenGL 3.3，独立于 Qt 窗口与显示服务器。
每个相机捕获线程拥有自己的上下文、标识纹理和原生尺寸帧缓冲；颜色和深度目标按尺寸复用。
直接以标定的 width/height、fx/fy/cx/cy 投影、遮挡和栅格化，最多使用 4 样本 MSAA，原生尺寸解析后直接读回 BGR8。
不再使用两倍宽高渲染后全图缩小；CPU 兼容路径同样使用原生尺寸。可选噪声仍在像素读回后按种子施加。
两种后端共用板面、圆弧端部灯条和 2026 标识定义，图像中不绘制世界评估用的击打点。
原生 GPU 用线性 / mipmap 纹理过滤平滑标识，圆弧灯条避免理想四顶点矩形被传统检测器的轮廓点数门槛过滤；未修改检测器。

构建默认 `RM_SIM_CAMERA_GPU=ON`，需要 EGL/OpenGL 开发库，找不到时自动构建 CPU 兼容路径。
无第三方依赖的 `core` 预设明确禁用此选项。GPU 强制回归可用
`cmake --preset test -DRM_SIM_TEST_GPU=ON` 启用（要求本机硬件 EGL 可用）；普通测试也覆盖原生 CPU 路径。
